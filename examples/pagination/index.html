Pagination

Lets users pick a page within a large set of results, with ellipsis, first/last buttons and a link mode for SSR.

Basic usage Variants Shapes Sizes Colors Buttons Ranges States Link mode Real-world examples Grid Programmatic usage Manual BEM usage

Basic usage

A single <nav data-mtx="pagination"> with data-count (total pages) and, optionally, data-page (1-based). The component generates the buttons, the ellipsis and the translated aria-labels.

<nav data-mtx="pagination" data-count="10"></nav>
<nav data-mtx="pagination" data-count="10" data-color="primary"></nav>

Ranges

data-sibling-count (1) sets how many pages are shown on each side of the current one and data-boundary-count (1) how many at the beginning and the end.

States

Hover over a page, use Tab to see focus and press to see the ripple. Previous/next disable themselves at the ends; data-disabled disables the whole component.

Link mode

With data-href-template each item is an <a href> ({page} is replaced with the number): it works with server-side rendering, opens in a new tab and needs no JavaScript to navigate. The ends are marked with aria-disabled.

<nav data-mtx="pagination" data-count="8" data-page="3" data-href-template="/blog?page={page}"></nav>

Real-world examples

A client-side paginated list of articles: the mtx:pagination:change event re-renders the list.

    In a grid

    Items wrap to a new line if they don't fit. On mobile, reduce data-sibling-count to 0 or use the small size.

    Programmatic usage

    goTo(n), next() and previous() emit mtx:pagination:change; assigning page or count updates without emitting.

    
      
    const pagination = Materix.getInstance(document.querySelector('#pg-api'));
pagination.element.addEventListener('mtx:pagination:change', (event) => {
  console.log(event.detail.page, event.detail.previousPage);
});
pagination.goTo(7);
pagination.count = 20;

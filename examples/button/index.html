Button

Action button with text, outlined and contained variants, three canonical heights (48/40/32px), palette colors and icons.

Basic usage

A single <button> with the variant class and data-mtx="button". The library adds the ripple and manages the disabled state; there is no inner structure to write.

<button class="mtx-button mtx-button--contained" data-mtx="button">Save</button>

Variants

Visual hierarchy is expressed with the variant: contained for the primary action, outlined for medium-emphasis secondary actions and text for low-emphasis actions (dialogs, cards).

Contained · high emphasis
Outlined · medium emphasis

Sizes

Three canonical heights with data-size: large 48px, medium 40px (default) and small 32px. Each row aligns the button with other controls of the same height to check that they share the baseline.

Large · 48px — next to IconButton large and FAB medium (48px)
Medium · 40px (default) — next to TextField small (40px)
Small · 32px — next to IconButton small and Chip (32px)

With icons

With data-start-icon / data-end-icon (like MUI's startIcon / endIcon) the Material icon name is enough: the button generates <span class="mtx-button__icon mtx-button__icon--start material-icons" aria-hidden="true"> (or --end). The icons are decorative because the text already names the action, and they move 4px closer to the edge (2px in small) as in MUI.

States

Hover to see the hover state, press to see the ripple and use Tab to see the visible focus. The native disabled attribute dims the button and removes it from the tab order.

Loading

With data-loading the button is disabled, gets aria-busy="true" and shows a decorative CircularProgress, like MUI's loading. data-loading-position chooses where: center (hides the text and keeps the width), start or end (replace the start or end icon). data-loading-indicator shows a text instead of the spinner. Click any button to see it load for 2 seconds.

Static · data-loading
Interactive · click → 2 s loading 

<button class="mtx-button mtx-button--contained" data-mtx="button" data-loading>Save</button>
<button class="mtx-button mtx-button--outlined" data-mtx="button" data-loading data-loading-position="start" data-start-icon="save">Save</button>

const button = Materix.getInstance(el);
button.setLoading(true);   // or: button.loading = true
await save();
button.setLoading(false);  // restores the previous disabled state

Full width

mtx-button--full-width takes 100% of the container (equivalent to MUI's fullWidth). Useful in narrow forms and on mobile.

No elevation

mtx-button--disable-elevation removes the shadow of the contained variant in all its states (equivalent to MUI's disableElevation).

Uppercase

The text is shown as written. Add mtx-button--uppercase for the uppercase style characteristic of Material Design 2.

As a link

If the action navigates to another page, use an <a href> with the same classes: it keeps link semantics (open in a new tab, copy URL) with the look of a button.

Grid layout

Inside mtx-grid, combine mtx-button--full-width with responsive columns: on mobile the buttons stack at full width and from 600px they spread into columns.

Programmatic usage

Get the instance with Materix.getInstance(el) to call disable() and enable(), or create new buttons with Materix.init(el). Button does not emit its own events: listen to the native click.

Manual BEM usage

      
For SSR or fine-grained control you can write the size classes directly (mtx-button--large, --small) instead of data-size, and the icon nested as material-icons inside mtx-button__icon (with mtx-button__icon--start / --end for the MUI offset). The instance binds without duplicating anything: data-start-icon does not add a second icon if one already exists on that side.

      

        
        
        
      

      
<button class="mtx-button mtx-button--contained mtx-button--large" data-mtx="button" type="button">
  <span class="mtx-button__icon" aria-hidden="true"><span class="material-icons">save</span></span>
  Save
</button>

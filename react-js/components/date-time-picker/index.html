Date Time Picker

Date, time, date-time and range pickers with a calendar, MD2 radial clock, popover, modal or static mode, limits and formats.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { DateTimePicker } from '@rubenchodev/materix-react';

DateTimePicker is a single component that covers DatePicker, TimePicker, DateTimePicker and their range versions (the aliases fix the mode for you). It renders a TextField with a mask and an end icon button, and opens a calendar or a clock. It follows the WAI-ARIA Date Picker Dialog pattern: an accessible dialog, a keyboard-navigable day grid and a radial clock operable with the arrow keys. Use it when the date or time must be valid and easy to pick; for a date the user knows by heart (e.g. date of birth) a TextField with mask="date" may be enough.

import { DatePicker, TimePicker, DateTimePicker, DateRangePicker } from '@rubenchodev/materix-react';
// or only this component:
import { DatePicker } from '@rubenchodev/materix-react/components/date-time-picker';

Basic usage#

Pick the component for the mode. Every TextField prop (label, variant, size, helperText, startIcon, name…) works the same way. The field also accepts typing: a mask matching the format is applied, and only digits, separators (/ - .), : and the AM/PM letters are allowed, depending on the mode.

Focus the calendar button and press Enter, or type in the field and press Alt+↓: focus moves to the selected day (or today). The full key map is in Accessibility.

Clock and 12-hour format#

The time view opens in keyboard mode by default (editable hour and minute cards, with ↑/↓; Enter on the minutes applies and closes). With timeView="dial" it opens the MD2 radial clock; the bottom-left button toggles between the two. ampm (or a format with hh/A) enables the 12-hour format with an AM/PM selector. views (['hours', 'minutes', 'seconds']), minutesStep, minTime and maxTime are passed to the clock.

Popover, modal and static#

  • Popover (default): drops down below the field (inside the TextField, as in vanilla), anchors to the right or opens upward if there’s not enough room. On screens 600px wide or less it’s shown centered over a dark backdrop, with aria-modal and a focus trap.
  • Modal (display="modal"): a centered dialog with an MD2 colored header on any screen size. Picking a day applies it at once (onChange) but keeps the dialog open; OK closes it.
  • Static (displayStatic or the Static* aliases): a calendar or clock embedded in the page, with no field and no OK/Cancel buttons; each choice calls onChange.

Limits, initial value and format#

minDate and maxDate disable the days outside the interval; they accept a Date, YYYY-MM-DD, the field’s own format or today/hoy. shouldDisableDate(date) disables specific days (they are skipped while navigating with the keyboard). defaultValue (uncontrolled) or value (controlled) accept a Date, a timestamp, ISO text or text in the active format.

Without format, the date order comes from the locale (en/en-US: MM/DD/YYYY; es, es-MX, en-GB…: DD/MM/YYYY, resolved with Intl). format defines how the value is displayed and typed (and derives the field mask). Tokens: YYYY/AAAA year, YY short year, MM month, DD day, HH hour 0-23, hh hour 1-12, mm minutes, ss seconds, A AM/PM and a am/pm. mask replaces the automatic mask.

Language and texts#

The texts (Today, Cancel, OK, accessible names…) come from the Materix i18n system: the locale prop, then the I18nProvider and <html lang>. Regional codes are reduced to their base language for the texts (es-MX → es) while the full code is used with Intl (date order and accessible day names). Months and weekdays come from the dictionary when the language is registered and from Intl.DateTimeFormat otherwise (e.g. fr-FR). todayText, cancelText, okText and clearText replace the button texts, and actions chooses the buttons (today, clear, cancel, accept).

Programmatic usage#

value/onChange make it controlled; open/onOpen/onClose control the popover. The action ref is the equivalent of vanilla’s methods.

Programmatic usage open_in_new
import { useRef, useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { DateRangePicker, DateTimePicker } from '@rubenchodev/materix-react/components/date-time-picker';
import type {
  DateRange,
  DateTimePickerActions,
  DateTimePickerValue,
} from '@rubenchodev/materix-react/components/date-time-picker';

export default function Demo() {
  const action = useRef<DateTimePickerActions>(null);
  const [value, setValue] = useState<Date | null>(null);
  const [range, setRange] = useState<DateRange>({ start: null, end: null });
  const [log, setLog] = useState<string[]>([]);
  const write = (message: string) =>
    setLog((prev) => [`${new Date().toLocaleTimeString()}  ${message}`, ...prev].slice(0, 20));

  const actions: Array<[string, () => void]> = [
    ['open()', () => action.current?.open()],
    ["value = '2026-12-25 20:00'", () => setValue(new Date(2026, 11, 25, 20, 0))],
    ['value = new Date()', () => setValue(new Date())],
    [
      "time = '09:15'",
      () =>
        setValue((prev) => {
          const base = prev ? new Date(prev) : new Date();
          base.setHours(9, 15, 0, 0);
          return base;
        }),
    ],
    ['read value', () => write(`value ${value ? value.toString() : 'null'} · iso ${value ? value.toISOString() : 'null'}`)],
    ["range = ['2026-10-01', '2026-10-15']", () => setRange({ start: new Date(2026, 9, 1), end: new Date(2026, 9, 15) })],
    ['read range', () => write(`range ${JSON.stringify(range)}`)],
    [
      'clear()',
      () => {
        action.current?.clear();
        setRange({ start: null, end: null });
      },
    ],
  ];

  return (
    <div className="demo-stack">
      <div className="demo-grid-2">
        <div className="demo-group">

Standalone DateCalendar#

DateCalendar is the calendar used by the pickers: single or range selection, month and year views (view/onViewChange), visible month (month/onMonthChange), minDate, maxDate and shouldDisableDate. It has no surface of its own: place it in a Paper or a card.

Standalone DateCalendar open_in_new
import { useState } from 'react';
import { Paper } from '@rubenchodev/materix-react/components/paper';
import { DateCalendar } from '@rubenchodev/materix-react/components/date-time-picker';
import type { DateRange } from '@rubenchodev/materix-react/components/date-time-picker';

const isWeekend = (date: Date) => date.getDay() === 0 || date.getDay() === 6;

export default function Demo() {
  const [date, setDate] = useState<Date | null>(null);
  const [range, setRange] = useState<DateRange>({ start: null, end: null });
  return (
    <div className="demo-grid-2">
      <div className="demo-stack">
        <Paper variant="outlined" className="mtx-p-2" role="group" aria-label="Weekday calendar">
            <DateCalendar value={date} onChange={setDate} shouldDisableDate={isWeekend} />
        </Paper>
        <p className="demo-status" aria-live="polite">
          Weekdays only · {date ? date.toDateString() : 'none'}
        </p>
      </div>
      <div className="demo-stack">
        <Paper variant="outlined" className="mtx-p-2" role="group" aria-label="Range calendar">
            <DateCalendar range rangeValue={range} onRangeChange={setRange} minDate={new Date()} />
        </Paper>
        <p className="demo-status" aria-live="polite">
          Range · {range.start ? range.start.toDateString() : '…'} – {range.end ? range.end.toDateString() : '…'}
        </p>
      </div>
    </div>
  );
}

onChange detail#

{ value, date, dateTime, time, iso, isRange, startDate, endDate, range: { start, end } }, the same as vanilla’s detail (without picker). onChange fires once per applied selection: a day in date mode, the range end, each time change, Today, OK, typing a complete valid value, or clearing. In a complete range, date, dateTime and iso refer to the range end, as in vanilla.

warning

Cancel closes without reverting changes already emitted. As in vanilla, every applied change calls onChange immediately (a day in the modal, each hour or minute), so Cancel only discards what was not applied yet (for example the day picked in DateTimePicker before choosing the time). Clear calls onChange and onAccept with null.

In controlled mode the field always shows value: if the parent ignores onChange, the field and the calendar go back to value.

Accessibility#

  • Field: a TextField with <label for>, mask and aria-describedby. Clicking the field opens the picker without stealing focus; Alt+↓ (or ↓ when it’s open) moves focus into it.
  • Button: aria-label (Choose date, Choose time, Choose date and time, Choose date range, plus the current value), aria-haspopup="dialog", aria-expanded and aria-controls. Disabled together with the field.
  • Dialog: role="dialog" with an i18n aria-label; the modal (and the popover on screens ≤ 600px) adds aria-modal="true" and traps Tab. On open, focus goes to the selected day or today; Esc closes it (only if it’s the top layer) and returns focus. In popover mode, tabbing out closes it; only one picker is open at a time.
  • Calendar: role="grid" labelled by the month/year title (aria-live), columnheader cells with full weekday names and one row per week. Each day is a gridcell with a full aria-label (Tuesday, October 20, 2026), aria-selected, aria-current="date" for today and aria-disabled. Roving tabindex; disabled days are skipped.
  • Months and years: role="radiogroup" with radio options, aria-checked and roving tabindex.
  • Clock: role="slider" with aria-valuemin/max/now and aria-valuetext; cards and AM/PM expose aria-label and aria-pressed; the tabs follow the Tabs pattern.

Stepper

Shows progress through a sequence of numbered steps, horizontal or vertical, linear or with clickable steps, plus its compact mobile version.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Stepper, Step, StepLabel, StepContent, MobileStepper, useStepper, StepperButton, StepPanel } from '@rubenchodev/materix-react';

Stepper conveys progress through a process split into steps (sign-up, checkout, setup wizard): which step is active, which are completed and which are still ahead. Use it when order matters and each step makes sense on its own. Don’t use it to switch between views at the same level (use Tabs) or to show the progress of an ongoing operation (use Progress).

Import#

import {
  Stepper,
  Step,
  StepLabel,
  StepContent,
  MobileStepper,

Basic usage#

The shortest form is a <Stepper> with a steps array of labels. The component renders the semantic <ol>, the 24px numbered icon, the connectors and the accessible text (“Step 2 of 3”), and marks the active step with aria-current="step". defaultActiveStep (uncontrolled) or activeStep (controlled) is the zero-based index of the active step.

Basic usage open_in_new

Each entry of steps can also be an object with the Step props ({ label, optional, error, completed, disabled, icon, expanded, content }), or you can write <Step> children.

Linear with actions#

In linear mode (the default), steps before the active one are considered completed and the following ones disabled. useStepper() links a stepper through apiRef and exposes its state; StepperButton action="back|next|reset" drives it and disables itself on the first step (back) or once finished (next) unless keepEnabled; StepPanel shows the panel of the active step, and index="finished" the final panel once activeStep reaches the number of steps.

Responsive behavior

Below 600px, a horizontal stepper without alternative label only shows the label of the active step; the others are visually hidden but still available to screen readers. If every label must be visible on mobile, use alternativeLabel or the vertical orientation.

Mobile stepper#

MobileStepper is MUI’s compact version: it renders the Back/Next buttons and a dots (default), text (“2 / 5”) or progress indicator (reusing LinearProgress). position="bottom|top" pins it to the edge of the window. backButton/nextButton replace the generated buttons with your own nodes; if they carry the mtx-mobile-stepper__back / mtx-mobile-stepper__next class, clicking them navigates.

Real-world examples#

An account sign-up wizard with validation: the cancelable onChange returns false to prevent moving forward while the TextField email is invalid, and marks the step and the field with an error (setError(), error + helperText).

Real-world examples open_in_new
import { useState } from 'react';
import { Paper } from '@rubenchodev/materix-react/components/paper';
import { TextField } from '@rubenchodev/materix-react/components/text-field';
import { Typography } from '@rubenchodev/materix-react/components/typography';
import {
  StepPanel,
  Stepper,
  StepperButton,
  useStepper,
  type StepperChangeHandler,
} from '@rubenchodev/materix-react/components/stepper';

export const description = {
  en: "A sign-up wizard with validation: the cancelable `onChange` returns `false` while the email is invalid and marks the step with `setError()`.",
  es: "Un asistente de alta con validación: el `onChange` cancelable devuelve `false` mientras el email no sea válido y marca el paso con `setError()`.",
};

const EMAIL = /^[^@\s]+@[^@\s]+\.[^@\s]+$/;

export default function Demo() {
  const stepper = useStepper();
  const [email, setEmail] = useState('');
  const [showError, setShowError] = useState(false);
  const isValid = EMAIL.test(email);

  // Cambio cancelable: no se avanza desde el primer paso con un email inválido.
  const handleChange: StepperChangeHandler = (activeStep, { previousStep }) => {
    if (previousStep === 0 && activeStep > 0) {
      stepper.setError(0, isValid ? false : 'Enter a valid email');
      setShowError(!isValid);
      if (!isValid) return false;
    }
    return undefined;
  };

  return (
    <div className="demo-surface">
      <Paper variant="outlined" className="demo-wide">
        <div className="demo-stack mtx-p-3">
          <Stepper
            apiRef={stepper.apiRef}
            alternativeLabel
            label="Account sign-up"
            onChange={handleChange}
            steps={['Account', 'Company', 'Plan']}
          />
          <StepPanel stepper={stepper} index={0}>
            <TextField
              label="Work email"
              variant="outlined"
              type="email"
              required
              value={email}
              onChange={(_, value) => {
                setEmail(value);
                if (showError && EMAIL.test(value)) {
                  setShowError(false);
                  stepper.setError(0, false);
                }
              }}
              error={showError}
              helperText={showError ? 'Enter a valid email' : undefined}
            />
          </StepPanel>
          <StepPanel stepper={stepper} index={1}>
            <TextField label="Company name" variant="outlined" />
          </StepPanel>
          <StepPanel stepper={stepper} index={2}>
            <Typography variant="body2">Team plan · $12 per user per month.</Typography>
          </StepPanel>
          <StepPanel stepper={stepper} index="finished">
            <Typography variant="body2">Your account is ready.</Typography>
          </StepPanel>
          <div className="demo-row">
            <StepperButton action="back" stepper={stepper}>
              Back
            </StepperButton>
            <StepperButton action="next" stepper={stepper} variant="contained">
              Next
            </StepperButton>
          </div>
        </div>
      </Paper>
    </div>
  );
}
const handleChange: StepperChangeHandler = (activeStep, { previousStep }) => {
  if (previousStep === 0 && activeStep > 0) {
    const valid = EMAIL.test(email);
    stepper.setError(0, valid ? false : 'Enter a valid email');
    if (!valid) return false;
  }
};

Programmatic usage#

apiRef exposes next(), back(), goTo(i), reset(), setCompleted(i, bool), setError(i, message|false), setDisabled(i, bool), isCompleted(i) and the activeStep, length and finished getters. Every change goes through onChange, which can cancel it.

Programmatic usage open_in_new
import { useRef, useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Stepper, type StepperApi } from '@rubenchodev/materix-react/components/stepper';

export const description = {
  en: "`apiRef` exposes `next()`, `back()`, `goTo()`, `reset()`, `setCompleted()`, `setError()` and `activeStep`; every change goes through `onChange`.",
  es: "`apiRef` expone `next()`, `back()`, `goTo()`, `reset()`, `setCompleted()`, `setError()` y `activeStep`; todo cambio pasa por `onChange`.",
};

export default function Demo() {
  const api = useRef<StepperApi>(null);
  const [log, setLog] = useState<string[]>([]);
  const write = (text: string) => setLog((lines) => [text, ...lines].slice(0, 8));
  const run = (fn: (stepper: StepperApi) => void) => {
    if (api.current) fn(api.current);
  };

  return (
    <div className="demo-stack">
      <Stepper
        apiRef={api}
        nonLinear
        label="API"
        steps={['One', 'Two', 'Three', 'Four']}
        onChange={(activeStep, { previousStep }) => {
          write(`onChange → activeStep ${activeStep}, previousStep ${previousStep}`);
        }}
      />
      <div className="demo-row">
        <Button variant="outlined" size="small" onClick={() => run((s) => s.back())}>
          back()
        </Button>
        <Button variant="outlined" size="small" onClick={() => run((s) => s.next())}>
          next()
        </Button>
        <Button variant="outlined" size="small" onClick={() => run((s) => s.goTo(3))}>
          goTo(3)
        </Button>
        <Button
          variant="outlined"
          size="small"
          onClick={() =>
            run((s) => {
              s.setCompleted(s.activeStep, !s.isCompleted(s.activeStep));
              write(`setCompleted(${s.activeStep})`);
            })
          }
        >
          setCompleted(active)
        </Button>
        <Button
          variant="outlined"
          size="small"
          onClick={() =>
            run((s) => {
              s.setError(s.activeStep, 'Check this step');
              write(`setError(${s.activeStep})`);
            })
          }
        >
          setError(active)
        </Button>
        <Button
          variant="outlined"
          size="small"
          onClick={() =>
            run((s) => {
              s.reset();
              write('reset()');
            })
          }
        >
          reset()
        </Button>
      </div>
      <pre className="demo-log" aria-live="polite">
        {log.join('\n')}
      </pre>
    </div>
  );
}
const api = useRef<StepperApi>(null);

API reference#

Stepper props#

PropTypeDefaultDescription
activeStepnumber—Active step (controlled). Equal to the number of steps = finished.
defaultActiveStepnumber0Initial active step (uncontrolled).
onChange(activeStep, detail) => boolean | void—Before the step changes (click, button or API). Return false or call detail.preventDefault() to cancel. detail: { activeStep, previousStep, reset? }.
orientation'horizontal' | 'vertical''horizontal'Orientation. In vertical, step children are a collapsible StepContent.
alternativeLabelbooleanfalseLabel below the icon (horizontal only).
nonLinearbooleanfalseClickable steps (<button>); completion is not inferred from the order.
stepsArray<string | StepDefinition>—Steps as data instead of <Step> children.
labelstring—aria-label of the <ol>.
localestringcontextLanguage of the accessible texts.
apiRefRef<StepperApi>—Imperative API (see below).

ref, className, style and other attributes go to the <ol>.

Step props#

PropTypeDefaultDescription
labelReactNode—Label. Without it, a Step whose children are plain content uses them as the label.
optionalboolean | ReactNode—Translated “Optional” caption, or the given text.
completedbooleanfrom the order (linear)Forces the completed state (false prevents it).
errorboolean | string—Error state with a warning icon; the text is shown as the message.
disabledbooleanfalseStep cannot be activated (<button disabled> in non-linear).
iconReactNodenumberCustom icon: Material Icons name or node.
expandedbooleanfalseIn vertical, keeps the content expanded even when not active.
childrenReactNode—StepContent (with label) or manual parts (StepLabel, StepContent).

StepLabel: children (label), optional, icon and disableRipple (override the Step values). StepContent, StepConnector and StepIcon (icon, active, completed, error) are also exported.

Accessibility#

  • A semantic <ol> is used: the order of the steps is part of the meaning. Name it with label or aria-label.
  • The active step carries aria-current="step" (on the <li>, or on its <button> in non-linear mode).
  • Each step includes hidden text with its position and state: “Step 2 of 3: Shipping, completed”. Icons and connectors are decorative (aria-hidden). Texts are translated with the I18nProvider locale or the locale prop.
  • In non-linear mode steps are native <button> elements with visible focus; disabled ones use disabled.
  • In vertical, the content of collapsed steps is marked inert and aria-hidden so it cannot receive focus.
  • MobileStepper announces the current step in an aria-live="polite" region; dots and the bar are decorative.
  • Honors prefers-reduced-motion.

Button

Action button with text, outlined and contained variants, three canonical heights (48/40/32px), palette colors, icons and loading state.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Button } from '@rubenchodev/materix-react';

Button lets users take an action or confirm a decision with a single click: submit a form, open a dialog, send a message. Use it when the action has a text label that describes it. If the action can only be represented by an icon, use Icon Button; if it’s the primary, persistent action of the whole screen, use a Fab. To navigate to another page, pass href and the button renders an <a>.

lightbulb

Button, Icon Button or Fab?

ComponentWhen to use itExample
ButtonAction with a text label; hierarchy through the variant.“Save”, “Cancel”
Icon ButtonCompact action recognizable by its icon, in toolbars or rows.Search, close, more options
FabThe primary action of the screen, floating above the content.Compose email, create event

Import#

import { Button } from '@rubenchodev/materix-react';
// or only this component
import { Button } from '@rubenchodev/materix-react/components/button';

The component imports its own CSS (button.css and progress.css for the loading spinner). Import @rubenchodev/materix-ui/base.css once in your app.

Basic usage#

A single <Button> with its variant. The component renders a native <button type="button">, adds the ripple and manages the disabled state; there’s no inner structure to write.

Basic usage open_in_new
import { Button } from '@rubenchodev/materix-react/components/button';

export default function Demo() {
  return (
    <div className="demo-row">
      <Button variant="contained">Save</Button>
      <Button variant="outlined">Preview</Button>
      <Button>Cancel</Button>
    </div>
  );
}

Variants#

Visual hierarchy is expressed through the variant, just like in MUI:

  • Contained (variant="contained"): high emphasis, filled and elevated. Reserved for the primary action; ideally one per block.
  • Outlined (variant="outlined"): medium emphasis, for important secondary actions.
  • Text (variant="text", default): low emphasis, for actions in dialogs, cards or next to a contained button.

With icons#

startIcon and endIcon accept the Material Icons ligature name (startIcon="add") or any node (an <svg>, another icon font). The button wraps them in <span class="mtx-button__icon mtx-button__icon--start" aria-hidden="true"> (or --end), adds material-icons when you pass a name, and moves them 4px towards the edge (2px on small) as in MUI. The icons are decorative because the text already names the action; an <svg> renders at 24 × 24px with currentColor.

With iconOnly the button becomes square and circular (48/40/32px depending on the size). It requires an aria-label. For icons without a background, Icon Button is preferable.

Colors#

Primary is the default color. color accepts secondary, success, error, warning, info and inherit in all three variants. With inherit text and outlined take the container’s color: use it on dark or colored surfaces (AppBar, banners, calls to action).

On a colored surface#

surface="primary" (or secondary) adapts the button to a background of that color: contained is inverted (paper background with primary text, mtx-button--on-primary) and text/outlined take the container’s color.

AA contrast#

Buttons meet WCAG AA (4.5:1) by default: text and outlined use --mtx-color-{color}-text and contained warning/info use dark text. To get MUI’s exact colors, add data-mtx-contrast="mui" to <html> or a container.

Loading#

With loading the button enters a loading state like MUI’s loading: it gets disabled (disabled, or aria-disabled on links), receives aria-busy="true" and shows a decorative 16px CircularProgress in the text color. loadingPosition picks the position: center (default; the label becomes transparent and the width doesn’t change), start or end (they replace the start or end icon without changing the width; without an icon, the indicator is added on that side). loadingIndicator shows a text (or any node) instead of the spinner.

When loading goes back to false, the previous state returns: a button with disabled stays disabled. The button keeps its accessible name; to announce progress, add your own aria-live region.

Loading open_in_new
import { useEffect, useRef, useState } from 'react';
import { Button, type ButtonOwnProps } from '@rubenchodev/materix-react/components/button';

interface LoadingOnClickProps extends ButtonOwnProps {
  onStatus: (text: string) => void;
}

/** Botón que entra en carga 2 s al hacer clic. */
function LoadingOnClick({ onStatus, ...props }: LoadingOnClickProps) {
  const [loading, setLoading] = useState(false);
  const timer = useRef<ReturnType<typeof setTimeout>>(undefined);
  useEffect(() => () => clearTimeout(timer.current), []);
  const handleClick = () => {
    setLoading(true);
    onStatus('Saving…');
    timer.current = setTimeout(() => {
      setLoading(false);
      onStatus('Changes saved');
    }, 2000);
  };
  return <Button {...props} loading={loading} onClick={handleClick} />;
}

export default function Demo() {
  const [status, setStatus] = useState('');
  return (
    <div className="demo-stack">
      <div className="demo-group">
        <span className="demo-label">Static · loading</span>
        <div className="demo-row">
          <Button variant="contained" loading>Save</Button>
          <Button variant="outlined" loading loadingPosition="start" startIcon="save">Save</Button>
          <Button loading loadingPosition="end" endIcon="send">Send</Button>
          <Button variant="outlined" loading loadingIndicator="Loading…">Download</Button>
        </div>
      </div>
      <div className="demo-group">
        <span className="demo-label">Interactive · click → 2 s loading</span>
        <div className="demo-row">
          <LoadingOnClick variant="contained" onStatus={setStatus}>Save</LoadingOnClick>
          <LoadingOnClick variant="contained" loadingPosition="start" startIcon="save" onStatus={setStatus}>
            Save
          </LoadingOnClick>
          <LoadingOnClick variant="outlined" loadingPosition="end" endIcon="send" onStatus={setStatus}>
            Send
          </LoadingOnClick>
          <LoadingOnClick variant="outlined" loadingIndicator="Paying…" onStatus={setStatus}>
            Pay $49
          </LoadingOnClick>
          <LoadingOnClick variant="contained" size="small" onStatus={setStatus}>Small</LoadingOnClick>
          <LoadingOnClick variant="contained" size="large" onStatus={setStatus}>Large</LoadingOnClick>
        </div>
        <p className="demo-status" role="status" aria-live="polite">
          {status}
        </p>
      </div>
    </div>

As a link#

If the action navigates to another URL, pass href: the button renders an <a> and keeps link semantics (open in a new tab, copy the address) with the look of a button. Since <a> doesn’t support disabled, a disabled link gets aria-disabled="true", tabindex="-1" and its click is blocked.

To use a router link, pass it in component (<Button component={RouterLink} href="/plans">). Any other element (component="span") receives role="button", tabindex="0" and activation with Enter/Space.

As a link open_in_new
import { Button } from '@rubenchodev/materix-react/components/button';

Programmatic usage#

In React the state lives in props: disabled, loading and the rest are controlled by your state. ref points to the root DOM element (focus(), measurements). Button doesn’t emit its own events: use onClick and the other native handlers.

Programmatic usage open_in_new
import { useRef, useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';

export default function Demo() {
  const [disabled, setDisabled] = useState(false);
  const [extra, setExtra] = useState<number[]>([]);
  const [log, setLog] = useState<string[]>([]);
  const ref = useRef<HTMLButtonElement>(null);
  const write = (text: string) =>
    setLog((lines) => [`[${new Date().toLocaleTimeString()}] ${text}`, ...lines].slice(0, 8));

  const changeDisabled = (value: boolean) => {
    setDisabled(value);
    write(`disabled = ${value}`);
  };

  return (
    <div className="demo-stack">
      <div className="demo-group">
        <span className="demo-label">Controlled button</span>
        <div className="demo-row">
          <Button ref={ref} variant="contained" disabled={disabled} onClick={() => write('click on "Controlled button"')}>
            Controlled button
          </Button>
        </div>
        <p className="demo-status">disabled: {String(disabled)}</p>
      </div>
      <div className="demo-group">
        <span className="demo-label">Actions</span>
        <div className="demo-row">
          <Button variant="outlined" size="small" onClick={() => changeDisabled(true)}>
            Disable
          </Button>
          <Button variant="outlined" size="small" onClick={() => changeDisabled(false)}>
            Enable
          </Button>
          <Button
            variant="outlined"
            size="small"
            onClick={() => {
              ref.current?.focus();
              write('ref.current.focus()');
            }}
          >
            Focus (ref)
          </Button>
          <Button
            variant="outlined"
            size="small"
            onClick={() => {
              setExtra((list) => [...list, list.length + 1]);
              write('new <Button> rendered');
            }}
          >
            Add button
          </Button>
        </div>
        {extra.length ? (
          <div className="demo-row">
            {extra.map((n) => (
              <Button key={n} variant="outlined" size="small">
                New #{n}
              </Button>
            ))}
          </div>
        ) : null}
      </div>
      <div className="demo-group">
        <span className="demo-label">Event log</span>
        <pre className="demo-log" aria-live="polite">
          {log.join('\n')}
        </pre>
      </div>
    </div>
  );
}

Accessibility#

  • Use <Button> (a native <button>) for actions and href for navigation.
  • Icon-only buttons (iconOnly) need an aria-label. Icons next to text have aria-hidden="true".
  • disabled removes the button from the tab order. On links, it applies aria-disabled="true" and tabindex="-1" and blocks the click.
  • While loading, the button is disabled with aria-busy="true" and keeps its accessible name. The indicator is aria-hidden.
  • The ripple respects prefers-reduced-motion.

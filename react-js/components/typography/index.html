Typography

Applies the MUI type scale (h1 to overline) to any element, separating HTML semantics from visual style.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Typography } from '@rubenchodev/materix-react';

Typography applies MUI’s text styles (headings, subtitles, body, button, caption and overline) with the Roboto font and the theme tokens. Use it so that all the text in the interface shares a single scale. You don’t need it for text already styled by its component (buttons, fields, lists…).

import { Typography } from '@rubenchodev/materix-react';
// or only this component:
import { Typography } from '@rubenchodev/materix-react/components/typography';

Basic usage#

Without props, <Typography> is a body1 paragraph. variant picks the style and component the tag.

Basic usage open_in_new
import { Typography } from '@rubenchodev/materix-react/components/typography';

export default function Demo() {
  return (
    <div>
      <Typography component="h3" variant="h4" gutterBottom>
        Monthly report
      </Typography>
      <Typography variant="body1">Sales grew 12% over the previous month, driven by the online channel.</Typography>
    </div>
  );
}

Type scale#

The 13 MUI variants. As in MUI, no variant has margins (not even h1–h6): add them with gutterBottom (0.35em) or paragraph (16px).

Type scale open_in_new

Semantics vs. style#

component defines the document structure and variant the appearance, so you can keep a correct heading hierarchy regardless of the visual size. A heading component (h1–h6) without variant takes its variant from the tag, like vanilla.

Semantics vs. style open_in_new
import { Typography } from '@rubenchodev/materix-react/components/typography';

export default function Demo() {
  return (
    <div className="demo-panel">
      <Typography component="h3" variant="h5" gutterBottom>
        Semantic h3 styled as h5
      </Typography>
      <Typography component="h4" variant="subtitle1">
        Semantic h4 styled as subtitle1
      </Typography>
      <Typography variant="body2">Paragraph styled as body2.</Typography>
    </div>
  );
}

Margins and truncation#

gutterBottom adds a 0.35em bottom margin; paragraph adds 16px (and renders a <p> if there is no component); noWrap keeps the text on one line and truncates it with an ellipsis.

Margins and truncation open_in_new
import { Typography } from '@rubenchodev/materix-react/components/typography';

export default function Demo() {
  return (
    <div className="demo-grid-2">
      <div className="demo-group">
        <span className="demo-label">gutterBottom and paragraph</span>
        <div className="demo-panel">
          <div>
            <Typography variant="subtitle2" gutterBottom>
              Heading with gutterBottom
            </Typography>
            <Typography variant="body2" paragraph>
              Paragraph with a 16px bottom margin (paragraph).
            </Typography>
            <Typography variant="body2">Next paragraph.</Typography>
          </div>
        </div>
      </div>
      <div className="demo-group">
        <span className="demo-label">noWrap</span>
        <div className="demo-panel">
          <Typography noWrap className="demo-fixed-width">
            Very long text that doesn&apos;t fit on a single line and is truncated with an ellipsis.
          </Typography>
        </div>
      </div>
    </div>
  );
}

Responsive typography#

  • Variant per breakpoint (mobile-first; sm 600px, md 900px, lg 1200px, xl 1536px): variantSm, variantMd, variantLg and variantXl replace variant from that width up.
  • Fluid scale (MUI’s responsiveFontSizes): responsive scales h1–h6 with clamp() between their mobile and desktop sizes. The mtx-typography--responsive class also works on any ancestor (for example on <html>).
Responsive typography open_in_new
import { Typography } from '@rubenchodev/materix-react/components/typography';

export default function Demo() {
  return (
    <div className="demo-grid-2">
      <div className="demo-group">
        <span className="demo-label">Per breakpoint · h5 → md h4 → lg h3</span>
        <div className="demo-panel">
          <div>
            <Typography component="h2" variant="h5" variantMd="h4" variantLg="h3" gutterBottom>
              What&apos;s new in October
            </Typography>
            <Typography variant="body2" variantMd="body1">
              body2 on mobile, body1 from 900px
            </Typography>
          </div>
        </div>
      </div>
      <div className="demo-group">
        <span className="demo-label">Fluid scale · clamp()</span>
        <div className="demo-panel">
          <div>
            <Typography component="h2" variant="h2" responsive gutterBottom>
              Fluid headline
            </Typography>
            <Typography component="h3" variant="h4" responsive>
              Fluid subtitle
            </Typography>
          </div>
        </div>
      </div>
    </div>
  );
}

Grid#

KPIs in a grid: figure in h4, label in overline and change in caption.

Grid open_in_new
import { Grid } from '@rubenchodev/materix-react/components/grid';
import { Typography } from '@rubenchodev/materix-react/components/typography';

const kpis = [
  { label: 'Revenue', value: '$48,200', change: '+12% this month', color: 'success' as const },
  { label: 'Orders', value: '1,284', change: '+4% this month', color: 'success' as const },
  { label: 'Returns', value: '37', change: '+9% this month', color: 'error' as const },
];

export default function Demo() {
  return (
    <Grid container spacing={2}>
      {kpis.map(({ label, value, change, color }) => (
        <Grid key={label} xs={12} sm={4}>
          <div className="demo-panel">
            <Typography variant="overline" color="text-secondary">
              {label}
            </Typography>
            <Typography variant="h4" component="p">
              {value}
            </Typography>
            <Typography variant="caption" color={color}>
              {change}
            </Typography>
          </div>
        </Grid>
      ))}
    </Grid>
  );
}

Programmatic usage#

Typography has no state: render it from your data and change variant like any other prop.

Programmatic usage open_in_new
import { useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Typography, type TypographyVariant } from '@rubenchodev/materix-react/components/typography';

const variants: TypographyVariant[] = ['h5', 'h6', 'subtitle1', 'overline'];

export default function Demo() {
  const [count, setCount] = useState(0);
  const items = Array.from({ length: count }, (_, i) => ({ n: i + 1, variant: variants[i % variants.length] }));
  return (
    <div className="demo-stack">
      <div className="demo-row">
        <Button variant="outlined" onClick={() => setCount((n) => n + 1)}>
          Add dynamic heading
        </Button>
        <Button variant="text" onClick={() => setCount(0)}>
          Clear
        </Button>
      </div>
      <div>
        {items.map(({ n, variant }) => (
          <Typography key={n} variant={variant} component="p">
            Dynamic heading {n} ({variant})
          </Typography>
        ))}
      </div>
      <pre className="demo-log" aria-live="polite">
        {items.map(({ variant }) => `<Typography variant="${variant}"> → mtx-typography mtx-typography--${variant}`).join('\n')}
      </pre>
    </div>
  );
}

Any other prop (id, style, aria-*, events) is forwarded to the root element. The exported constant TYPOGRAPHY_VARIANT_MAPPING holds the default tags.

Callbacks#

Typography emits no events.

CSS classes#

ClassDescription
.mtx-typographyBase: no margins, theme font, primary text color.
.mtx-typography--h1 … --overlineOne class per variant.
.mtx-typography--color-{color}Palette, text and inherit colors.

.mtx-typography--responsiveFluid h1–h6 scale.

Accessibility#

  • Choose the tag by its function (h1–h6 for the hierarchy, p for paragraphs) with component, and the look with variant: screen readers navigate by tag, not by size.
  • Don’t skip heading levels to get a size. Subtitles render as <p> by default so they don’t create headings by accident.
  • Status colors and disabled must not be the only way to convey information; pair them with text.
  • Text truncated with noWrap is visually hidden: if it matters, offer it in full elsewhere (for example in a title).

<h2 data-mtx="typography"> (variant from the tag)<Typography component="h2">
data-color="error"color="error"
data-align="center"align="center"
data-gutter-bottom / data-paragraph / data-no-wrapgutterBottom / paragraph / noWrap
data-variant-md="h4"variantMd="h4"
data-responsiveresponsive

Differences: vanilla has no default variant on non-heading tags; React uses body1 like MUI (variant="inherit" reproduces the vanilla behavior). The tag is chosen from the variant when there is no component.

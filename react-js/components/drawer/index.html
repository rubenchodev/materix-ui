Drawer

Side panel for navigation or supplementary content: temporary, persistent, permanent or responsive, with a generated header and footer and an app shell pattern.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Drawer } from '@rubenchodev/materix-react';

Drawer is a panel that slides in from an edge of the screen to show the app’s navigation or supplementary content (filters, details, options), like MUI’s Drawer. Use it for primary navigation on mobile (temporary) or as a fixed sidebar on desktop (permanent). For a decision or a short form that interrupts the flow use a Dialog; for a short list of actions on an item, a Menu.

import { Drawer } from '@rubenchodev/materix-react/components/drawer';
// pieces for manual composition and the responsive hook:
import { DrawerHeader, DrawerContent, DrawerFooter, DrawerSubmenu, useDrawer, useDrawerMode } from '@rubenchodev/materix-react/components/drawer';

Basic usage#

<Drawer open={…} onClose={…} title="…"> with the content directly inside. title generates the header with a title and a close button; the content is wrapped in the scrollable panel .mtx-drawer__content, and the temporary drawer adds a Backdrop. open is controlled: onClose(event, reason) asks to close and you update the state.

The useDrawer() hook does that wiring for you, like usePopover and useMenu: it returns { open, setOpen, toggle, getTriggerProps(), drawerProps }. Spread getTriggerProps() on the trigger (it adds aria-controls, aria-expanded and onClick; pass { action: 'open' } so it only opens, like data-mtx-drawer-open) and drawerProps (id, open, onClose) on the Drawer. Thanks to aria-controls the trigger is not counted as a click outside.

const drawer = useDrawer();

<Button variant="contained" {...drawer.getTriggerProps({ action: 'open' })}>Open navigation</Button>
<Drawer {...drawer.drawerProps} title="Mail">…</Drawer>

App shell: AppBar + responsive Drawer#

The main recipe for an application: an AppBar, a row with a variant="responsive" drawer (temporary below breakpoint, permanent above it) and the main content. The AppBar connects to the drawer through its navigation button, the React equivalent of vanilla’s data-drawer="id":

  • navigationControls={drawerId} sets aria-controls on the menu button,
  • navigationExpanded={open} keeps aria-expanded in sync,
  • onNavigationClick toggles the state,
  • useDrawerMode('responsive', 'md') returns the current mode, so startIcon={mode === 'temporary' ? 'menu' : undefined} hides the button while the drawer is permanent (vanilla adds .mtx-drawer-trigger--hidden).

The drawer ignores clicks on its own trigger (any element with aria-controls pointing to its id), so the toggle doesn’t close and reopen it. Here the shell lives inside a frame (absolute); on a full page use clipped and a ToolbarOffset at the top of <main>.

Variants#

  • temporary (default): modal over a backdrop. It locks the page scroll, traps focus, closes with Escape, the backdrop or a click outside, and is rendered in a portal (the shared portal root [data-mtx-portal-root]; disablePortal keeps it in place). The backdrop is the Backdrop component (.mtx-backdrop, with its fade), not vanilla’s .mtx-drawer__backdrop.
  • persistent: opens without a backdrop and the page stays usable; move the content yourself to make room for it.
  • permanent: always visible, a fixed-width box in a flex row with a sticky panel of window height. It never asks to close.
  • responsive: see “Responsive”.

With absolute the drawer and its backdrop stay inside the positioned parent (no scroll lock), and the permanent drawer takes the container height.

Widths#

Responsive default: min(85vw, 320px) on mobile, 280px from 600px and 300px from 900px. width="narrow" | "wide" | "full" sets 200px, 360px or 100vw; any number (px) or CSS length ("40vw") is applied as is and also written to --mtx-drawer-width. It never exceeds 85% of the window except with full.

Under the AppBar (clipped)#

The AppBar spans the full width and the drawer starts below it. On a full page use clipped on a permanent, responsive or persistent drawer: it is placed at --mtx-app-bar-height (56px on mobile, 64px from 600px) and stacks under the AppBar (give the AppBar clipped too). The temporary drawer ignores clipped: it is modal and covers the AppBar, as in MUI. Inside a frame, as here, a permanent absolute drawer in the row under the AppBar achieves the same.

Responsive#

variant="responsive" with breakpoint="sm" | "md" | "lg" | "xl" (600, 900, 1200, 1536px; default md): below it the drawer is temporary and opens with its trigger; from it, permanent. When crossing the breakpoint, classes, ARIA, backdrop and focus are synced without animation, onModeChange(mode, previousMode) fires (vanilla mtx:drawer:mode-change), and an open temporary drawer asks to close with reason breakpoint so it doesn’t reappear when going back to mobile. If focus was inside when it becomes temporary, it moves to the visible trigger. The responsive drawer stays mounted and in place (no portal), so its content keeps its state. With SSR the server doesn’t know the viewport and renders the temporary mode; after hydration the drawer switches to the real mode without notifying onModeChange (vanilla doesn’t emit mode-change on init either). That first switch can still cause a jump on desktop: if it matters, render the shell only on the client or reserve the drawer width. headerMode="temporary" shows the generated header only while it is temporary. Resize the window.

Responsive: temporary on mobile, permanent on desktop open_in_new
import { useId, useState } from 'react';
import { AppBar } from '@rubenchodev/materix-react/components/app-bar';
import { Drawer, useDrawerMode } from '@rubenchodev/materix-react/components/drawer';
import type { DrawerBreakpoint, DrawerMode } from '@rubenchodev/materix-react/components/drawer';
import { List, ListItemButton } from '@rubenchodev/materix-react/components/list';
import { NativeSelect } from '@rubenchodev/materix-react/components/native-select';
import { Typography } from '@rubenchodev/materix-react/components/typography';

const folders = [
  { icon: 'inbox', label: 'Inbox' },
  { icon: 'star', label: 'Starred' },
  { icon: 'send', label: 'Sent' },
  { icon: 'drafts', label: 'Drafts' },
];

export default function Demo() {
  const navId = useId();
  const [breakpoint, setBreakpoint] = useState<DrawerBreakpoint>('md');
  const [open, setOpen] = useState(false);
  const [folder, setFolder] = useState('Inbox');
  const [log, setLog] = useState<string[]>([]);
  const mode = useDrawerMode('responsive', breakpoint);

  const handleModeChange = (next: DrawerMode, previous: DrawerMode) =>
    setLog((lines) => [...lines.slice(-3), `onModeChange: ${previous} → ${next}`]);

  return (
    <div className="demo-stack mtx-w-100">
      <div className="demo-fixed-width">
        <NativeSelect
          label="Breakpoint"
          value={breakpoint}
          onChange={(event) => setBreakpoint(event.target.value as DrawerBreakpoint)}
        >
          <option value="sm">sm · 600px</option>
          <option value="md">md · 900px</option>
          <option value="lg">lg · 1200px</option>
          <option value="xl">xl · 1536px</option>
        </NativeSelect>
      </div>
      <div className="demo-panel demo-panel--tall mtx-w-100">
        <div className="mtx-d-flex mtx-flex-column" style={{ height: 380 }}>
          <AppBar
            position="static"
            color="primary"
            title="Mail"
            startIcon={mode === 'temporary' ? 'menu' : undefined}
            navigationControls={navId}
            navigationExpanded={open}
            onNavigationClick={() => setOpen((value) => !value)}
          />
          <div className="mtx-position-relative mtx-d-flex mtx-flex-1 mtx-overflow-hidden">
            <Drawer
              id={navId}
              variant="responsive"
              breakpoint={breakpoint}
              absolute
              width={220}
              title="Mail"
              headerMode="temporary"
              aria-label="Folders"
              open={open}
              onClose={() => setOpen(false)}
              onModeChange={handleModeChange}
            >
              <List component="nav" aria-label="Folders">
                {folders.map((item) => (
                  <ListItemButton
                    key={item.label}
                    icon={item.icon}
                    selected={folder === item.label}
                    data-mtx-drawer-close
                    onClick={() => setFolder(item.label)}
                  >
                    {item.label}
                  </ListItemButton>
                ))}
              </List>
            </Drawer>
            <main className="mtx-flex-1 mtx-min-w-0 mtx-p-2">
              <Typography variant="subtitle1" component="h3" gutterBottom>
                {folder}
              </Typography>
              <Typography variant="body2" color="text-secondary">
                Current mode: <span aria-live="polite">{mode}</span>. Resize the window.
              </Typography>
            </main>
          </div>
        </div>
      </div>
      <pre className="demo-log" aria-live="polite">
        {log.join('\n')}
      </pre>
    </div>
  );
}

Collapsible submenus#

DrawerSubmenu is the equivalent of vanilla’s data-mtx-collapse-trigger + .mtx-collapse: a list item with aria-expanded and aria-controls, a .mtx-collapse-indicator that rotates 90°, and a nested List animated with Collapse. It works controlled (open + onToggle) or uncontrolled (defaultOpen). While collapsed its items are not focusable.

Grid layout#

A right drawer with width="wide" and padded containing a form laid out with Grid and TextField. inputProps={{ 'data-drawer-autofocus': '' }} gives the search field the initial focus (prefer it to autoFocus, which would steal the focus before the drawer records the trigger to return to). Buttons with data-mtx-drawer-close close it.

Programmatic usage#

The equivalent of open(), close(reason), toggle() and isOpen is the open prop, or setOpen, toggle and open from useDrawer. onOpen and onClose(event, reason) are the equivalents of mtx:drawer:open and mtx:drawer:close. The log shows the real callbacks: also try Escape, the backdrop and the X.

Programmatic usage open_in_new
import { useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Drawer, useDrawer } from '@rubenchodev/materix-react/components/drawer';

export default function Demo() {
  const [log, setLog] = useState<string[]>([]);
  const write = (text: string) => setLog((lines) => [...lines.slice(-7), text]);
  // El hook da el estado, setOpen/toggle (open()/close()/toggle() de vanilla) y las props de disparador y drawer.
  const drawer = useDrawer({
    onOpen: () => write('onOpen'),
    onClose: (reason) => write(`onClose · reason="${reason}"`),
  });

  return (
    <div className="demo-stack demo-wide">
      <div className="demo-row">
        <Button variant="outlined" {...drawer.getTriggerProps({ action: 'open' })}>
          setOpen(true)
        </Button>
        <Button variant="outlined" {...drawer.getTriggerProps()}>
          toggle()
        </Button>
        <Button onClick={() => write(`open → ${drawer.open}`)}>Read open</Button>
      </div>
      <pre className="demo-log" aria-live="polite">
        {log.join('\n')}
      </pre>
      <Drawer anchor="right" title="Programmatic control" padded {...drawer.drawerProps}>
        <p>Close it from here with setOpen(false).</p>
        <Button variant="contained" onClick={() => drawer.setOpen(false)}>
          Save and close
        </Button>
      </Drawer>
    </div>
  );
}

Manual BEM composition#

With DrawerHeader, DrawerContent and DrawerFooter as children the drawer generates nothing: it places the header and footer outside the scrollable panel and adds the dialog semantics to DrawerContent. Name the panel with aria-labelledby (or aria-label) on the drawer.

Accessibility#

  • temporary: the panel gets role="dialog", aria-modal="true" and tabindex="-1", named by the generated title or the drawer’s aria-label / aria-labelledby. Focus moves to the first element (or the one marked with data-drawer-autofocus), Tab stays inside and focus returns to the trigger on close. persistent gets role="region" and permanent role="navigation" (unless you pass role). The root keeps aria-hidden in sync.
  • Give the content a name: a <List component="nav" aria-label="…"> for navigation, or an aria-label on the drawer.
  • The generated close button’s aria-label comes from the i18n dictionary (drawer.close: “Close” / “Cerrar”).
  • Connect the trigger with aria-controls and aria-expanded (the AppBar does it with navigationControls and navigationExpanded).
  • Escape goes through the shared layer stack: a Menu or Popover opened inside the drawer closes first.
  • Respects prefers-reduced-motion: no slide or submenu transitions.
KeyAction
Enter / Space on the triggerOpens or closes the drawer.
Tab / Shift+TabMoves through the drawer; in temporary focus doesn’t leave it.
EscapeCloses the temporary drawer (unless disableEscapeKeyDown).
Enter / Space on a submenuExpands or collapses it.

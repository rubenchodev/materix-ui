Pagination

Lets users pick a page within a large set of results, with ellipsis, first/last buttons and a link mode for SSR.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Pagination, PaginationItem, usePagination } from '@rubenchodev/materix-react';

Pagination implements MUI’s Pagination: page buttons with ellipsis computed by the same algorithm as usePagination, previous/next buttons and optional first/last buttons, text and outlined variants, circular and rounded shapes, three sizes and three colors. Use it to move through result lists, blog articles or catalogs.

import '@rubenchodev/materix-ui/base.css';
import { Pagination } from '@rubenchodev/materix-react';

<Pagination count={10} />

Basic usage#

count (total pages) is enough. The component renders the <nav> landmark, the list, the buttons, the ellipsis and the translated aria-labels. It is uncontrolled by default (defaultPage, 1-based); use page + onChange to control it.

Basic usage open_in_new
import { Pagination } from '@rubenchodev/materix-react/components/pagination';

export default function Demo() {
  return (
    <div className="demo-stack">
      <Pagination count={10} aria-label="Basic pagination" />
      <Pagination count={10} color="primary" aria-label="Primary pagination" />
      <Pagination count={10} color="secondary" aria-label="Secondary pagination" />
      <Pagination count={10} disabled aria-label="Disabled pagination" />
    </div>
  );
}

States#

Items have hover, focus-visible (Tab) and ripple on press (disableRipple turns it off). Previous/next are disabled automatically at the ends; disabled disables the whole component. If the focused button becomes disabled (for example “next” on the last page), focus moves to the current page.

Link mode (SSR)#

With getItemHref(page) every item is an <a href>: it works with server-side rendering, can open in a new tab and needs no JavaScript to navigate. Items that cannot navigate get aria-disabled="true" and no href.

Link mode open_in_new
import { useState } from 'react';
import { Pagination } from '@rubenchodev/materix-react/components/pagination';

export default function Demo() {
  const [status, setStatus] = useState('Click a page: the navigation is cancelled and handled in the client.');
  return (
    <div className="demo-stack">
      <Pagination
        count={8}
        defaultPage={3}
        variant="outlined"
        shape="rounded"
        color="primary"
        aria-label="Link pagination"
        getItemHref={(page) => `?page=${page}`}
        onChange={(event, page) => {
          event.preventDefault();
          setStatus(`Navigation to ?page=${page} cancelled with preventDefault(); page updated in the client.`);
        }}
      />
      <span className="demo-status" aria-live="polite">
        {status}
      </span>
    </div>
  );
}
info

Cancelable navigation

In link mode, clicking a page calls onChange(event, page) before navigating. If you call event.preventDefault(), the native navigation is cancelled and the page changes in the client (useful to load the results with fetch while keeping the links for crawlers). This is the equivalent of the cancelable mtx:pagination:change event in vanilla.

Real-world example#

Client-side paginated article list built with List inside a Paper.

Real-world example open_in_new
import { useState } from 'react';
import { List, ListItem } from '@rubenchodev/materix-react/components/list';
import { Pagination } from '@rubenchodev/materix-react/components/pagination';
import { Paper } from '@rubenchodev/materix-react/components/paper';

const ARTICLES = [
  'Designing accessible forms',
  'A guide to color tokens',
  'Responsive type with clamp()',
  'Shadows and elevation in MUI',
  'Visible focus states',
  'Mobile navigation patterns',
  'Sortable, filterable tables',
  'Micro-interactions with ripple',
  'Dark mode without flashing',
  'Icons on a 24px grid',
  '12-column grids',
  'Dialogs and focus management',
];
const PER_PAGE = 3;

export default function Demo() {
  const [page, setPage] = useState(1);
  const start = (page - 1) * PER_PAGE;
  return (
    <div className="demo-stack">
      <Paper variant="outlined">
        <List aria-label="Articles" aria-live="polite">
          {ARTICLES.slice(start, start + PER_PAGE).map((name, index) => (
            <ListItem key={name} icon="article" secondary={`Article ${start + index + 1} of ${ARTICLES.length}`}>
              {name}
            </ListItem>
          ))}
        </List>
      </Paper>
      <Pagination
        count={Math.ceil(ARTICLES.length / PER_PAGE)}
        page={page}
        onChange={(_, next) => setPage(next)}
        color="primary"
        aria-label="Articles pagination"
      />
    </div>
  );
}

Controlled usage and usePagination#

In controlled mode the parent owns page, so it can be changed from outside (buttons, URL, store). usePagination exposes the same logic as MUI’s hook to build your own UI: it returns items ({ type, page, selected, disabled, onClick }), page and goTo.

Controlled usage and usePagination open_in_new
import { useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Stack } from '@rubenchodev/materix-react/components/stack';
import { Pagination, usePagination } from '@rubenchodev/materix-react/components/pagination';

const COUNT = 10;

export default function Demo() {
  const [page, setPage] = useState(1);
  const [log, setLog] = useState<string[]>([]);
  const go = (next: number, source: string) => {
    const clamped = Math.min(Math.max(1, next), COUNT);
    if (clamped === page) return;
    setLog((prev) => [`${source} → page ${clamped} (previous: ${page})`, ...prev].slice(0, 12));
    setPage(clamped);
  };
  const { items } = usePagination({ count: 5, defaultPage: 2 });

  return (
    <div className="demo-stack">
      <div className="demo-group">
        <span className="demo-label">Controlled Pagination</span>
        <Pagination
          count={COUNT}
          page={page}
          onChange={(_, next) => go(next, 'onChange (user)')}
          color="primary"
          showFirstButton
          showLastButton
          aria-label="Controlled pagination"
        />
        <Stack direction="row" spacing={1} wrap alignItems="center">
          <Button variant="outlined" size="small" onClick={() => go(page - 1, 'previous')}>
            previous
          </Button>
          <Button variant="outlined" size="small" onClick={() => go(page + 1, 'next')}>
            next
          </Button>
          <Button variant="outlined" size="small" onClick={() => go(7, 'page = 7')}>
            page = 7
          </Button>
          <span className="demo-status">page: {page}</span>
        </Stack>
        <pre className="demo-log" aria-live="polite">
          {log.join('\n')}
        </pre>
      </div>
      <div className="demo-group">
        <span className="demo-label">Custom UI with usePagination</span>
        <Stack component="nav" direction="row" spacing={1} wrap alignItems="center" aria-label="Custom pagination">
          {items.map(({ type, page: target, selected, disabled, onClick }, index) =>
            type === 'start-ellipsis' || type === 'end-ellipsis' ? (
              <span key={`${type}-${index}`} aria-hidden="true">
                …
              </span>
            ) : (
              <Button
                key={`${type}-${index}`}
                size="small"
                variant={selected ? 'contained' : 'text'}
                disabled={disabled}
                aria-current={selected ? 'page' : undefined}
                onClick={onClick}
              >
                {type === 'page' ? target : type}
              </Button>
            ),
          )}
        </Stack>
      </div>
    </div>
  );
}
const [page, setPage] = useState(1);

usePagination#

usePagination({ count, page, defaultPage, onChange, siblingCount, boundaryCount, showFirstButton, showLastButton, hidePrevButton, hideNextButton, disabled }) returns { items, page, count, goTo, setPage }. The pure function getPaginationItems(options) (import { getPaginationItems } from '@rubenchodev/materix-react') returns the raw list ('previous', 1, 'start-ellipsis'…), typed as PaginationItemEntry[].

warning

Router links

In link mode, if a router Link rendered through renderItem cancels the navigation itself, the uncontrolled component also detects it (it checks defaultPrevented again in a microtask). For a router-driven page, prefer the controlled mode: derive page from the URL.

Accessibility#

  • <nav> landmark with aria-label="pagination navigation" (translated through i18n pagination.label; your own aria-label or aria-labelledby wins). Give each pagination on the same page its own label.
  • Each page is a real <button> (or <a href> in link mode) labeled “Go to page N”; the current one has aria-current="page" and the label “page N”.
  • Navigation buttons: “Go to first/previous/next/last page”; their SVG icon is aria-hidden.
  • Items at the ends are disabled with disabled (or aria-disabled in link mode); focus never gets lost.

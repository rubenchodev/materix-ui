Card

A surface that groups content and actions about a single subject: header, image, text and buttons.

codeSource code play_circleDemo sources open_in_newMUI reference
Import import { Card, CardHeader, CardMedia, CardContent, CardActions, CardActionArea } from '@rubenchodev/materix-react';

Card groups the information and actions of a single item on an elevated surface: a product, a recipe, a profile. It is built from optional parts —header, media, content, actions and action area— that you can generate with shorthand props on Card or compose with subcomponents. Use it when the block is self-contained and scannable within a collection; for a generic surface without structure use Paper, and for dense lists use List.

import { Card, CardContent, CardActions } from '@rubenchodev/materix-react';
// or just this component:
import { Card } from '@rubenchodev/materix-react/components/card';

Basic usage#

title, subheader, avatar, actionIcon and image generate the header and the image (the equivalent of the vanilla single-element syntax); the content and actions are children: CardContent and CardActions.

Basic usage open_in_new
import { Card, CardActions, CardContent } from '@rubenchodev/materix-react/components/card';
import { IconButton } from '@rubenchodev/materix-react/components/icon-button';

export default function Demo() {
  return (
    <div className="demo-surface">
      <Card
        className="demo-fixed-width"
        avatar="R"
        title="Shrimp and Chorizo Paella"
        subheader="September 14, 2026"
        actionIcon="more_vert"
        image="https://images.unsplash.com/photo-1534080564583-6be75777b70a?auto=format&fit=crop&w=800&q=80"
      >
        <CardContent>
          A Mediterranean dish with bomba rice, saffron, free-range chicken and fresh vegetables, perfect for sharing.
        </CardContent>
        <CardActions>
          <IconButton icon="favorite" aria-label="Add to favorites" />
          <IconButton icon="share" aria-label="Share" />
        </CardActions>
      </Card>
    </div>
  );
}

Variants#

By default the card has elevation 1. variant="outlined" delimits it with a border and no shadow; raised raises it to 8 (like MUI’s raised); elevation accepts 0–8, 12, 16 and 24; square removes the radius. The h1–h6 and p styles inside CardContent have zero specificity, so Typography (or any mtx-typography--* class) always wins.

Header#

The header (.mtx-card__header) is generated when there is a title, subheader or avatar. A string avatar is painted as a primary Avatar with that text; any other node (for example an <Avatar>) is rendered as is. actionIcon adds an IconButton on the right (its name comes from actionLabel, default “Actions”), and action accepts any node instead.

Actions alignment#

Card actions are right-aligned by default, like dialog actions. Change it with align="start|center|end|between" on CardActions, or for every action row of a card with actionsAlign on Card (a row’s own align wins).

info

Deliberate deviation from MUI

MUI’s CardActions aligns its buttons to the left. Materix aligns them to the right by default so that cards and dialogs share the same action placement. Use align="start" (or actionsAlign="start" on the card) to get the original MUI layout.

Action area#

CardActionArea turns the image and text into a single clickable zone with ripple, hover and focus, without affecting the actions. It renders a <button type="button">, an <a> when it receives href, or any element through component (then it gets role="button", tabIndex={0} and Enter/Space). With clickable the whole card becomes interactive (role="button", ripple, Enter and Space).

Action area open_in_new
import { useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Card, CardActionArea, CardActions, CardContent, CardMedia } from '@rubenchodev/materix-react/components/card';

export default function Demo() {
  const [status, setStatus] = useState('');
  return (
    <div className="demo-stack">
      <div className="demo-surface">
        <div className="demo-group">
          <span className="demo-label">CardActionArea</span>
          <Card className="demo-fixed-width">
            <CardActionArea onClick={() => setStatus('Clicked the action area.')}>
              <CardMedia
                height={140}
                alt="Colorful domes of Saint Basil's Cathedral"
                image="https://images.unsplash.com/photo-1513326738677-b964603b136d?auto=format&fit=crop&w=800&q=80"
              />
              <CardContent>
                <div className="mtx-card__title">Discover Moscow</div>
                <div>Colorful domes, museums and the most ornate subway in the world.</div>
              </CardContent>
            </CardActionArea>
            <CardActions>
              <Button>Book</Button>
              <Button>Save</Button>
            </CardActions>
          </Card>
        </div>
        <div className="demo-group">
          <span className="demo-label">Clickable card</span>
          <Card
            variant="outlined"
            clickable
            avatar="S"
            title="Settings"
            subheader="Account, privacy and notifications"
            className="demo-fixed-width"
            onClick={() => setStatus('Clicked the clickable card.')}

            <CardContent>The whole card responds to clicks and the keyboard.</CardContent>
          </Card>
        </div>
      </div>
      <p className="demo-status" role="status">
        {status}
      </p>
    </div>
  );
}

States#

Normal, hover and focus (hover or use Tab) and disabled. disabled on a clickable card or on CardActionArea lowers the opacity, removes the pointer and takes it out of the tab order (aria-disabled="true"; on a <button> also the native disabled).

Elevation in the dark theme#

In dark mode, as in MUI, each elevation adds a white overlay (--mtx-overlay-elevation-N): elevation 0 has no overlay, the card raised to 8 looks lighter than the elevation 1 card, and outlined has no overlay.

Programmatic usage#

The vanilla methods become props and refs: disabled replaces disable()/enable(), ref.current.focus() replaces focus() and the image prop of CardMedia replaces its setter. There are no mtx:* events: use onClick (also fired by Enter and Space on non-native elements).

Programmatic usage open_in_new
import { useRef, useState } from 'react';
import { Button } from '@rubenchodev/materix-react/components/button';
import { Card, CardActionArea, CardContent, CardMedia } from '@rubenchodev/materix-react/components/card';

const images = [
  'https://images.unsplash.com/photo-1513326738677-b964603b136d?auto=format&fit=crop&w=800&q=80',
  'https://images.unsplash.com/photo-1555881400-74d7acaacd8b?auto=format&fit=crop&w=800&q=80',
];

export default function Demo() {
  const cardRef = useRef<HTMLDivElement>(null);
  const [cardDisabled, setCardDisabled] = useState(false);
  const [areaDisabled, setAreaDisabled] = useState(false);
  const [image, setImage] = useState(0);
  const [log, setLog] = useState<string[]>([]);
  const write = (text: string) => setLog((prev) => [...prev.slice(-5), `${new Date().toLocaleTimeString()}  ${text}`]);

  return (
    <div className="demo-stack">
      <div className="demo-surface">
        <Card
          ref={cardRef}
          clickable
          disabled={cardDisabled}
          variant="outlined"
          avatar="S"
          title="Settings"
          subheader="Clickable card"
          className="demo-fixed-width"
          onClick={() => write('click  clickable card')}
        >
          <CardContent>The whole card is interactive.</CardContent>
        </Card>
        <Card className="demo-fixed-width">
          <CardActionArea disabled={areaDisabled} onClick={() => write('click  action area')}>
            <CardMedia height={120} alt="City view" image={images[image]} />
            <CardContent>Action area</CardContent>
          </CardActionArea>
        </Card>
      </div>
      <div className="demo-row">
        <Button
          variant="outlined"
          onClick={() => {
            setCardDisabled(true);
            write('card disabled={true}');
          }}
        >
          Disable card
        </Button>
        <Button
          variant="outlined"
          onClick={() => {
            setCardDisabled(false);
            write('card disabled={false}');
          }}
        >
          Enable card
        </Button>
        <Button
          variant="outlined"
          onClick={() => {
            cardRef.current?.focus();
            write('cardRef.current.focus()');
          }}
        >
          Focus card
        </Button>
        <Button
          variant="outlined"
          onClick={() => {
            setAreaDisabled((value) => !value);
            write('action area disabled toggled');
          }}
        >
          Toggle action area
        </Button>
        <Button
          variant="outlined"
          onClick={() => {
            setImage((index) => (index + 1) % images.length);
            write('CardMedia image changed');
          }}
        >
          Swap image
        </Button>
      </div>
      <pre className="demo-log" aria-live="polite">
        {log.join('\n')}
      </pre>
    </div>
  );
}

Callbacks#

Card emits no mtx:* events in vanilla either. Use the native onClick on Card clickable or CardActionArea.

CSS classes#

The same as the vanilla library: .mtx-card, --outlined, --elevation-{n}, --raised, --square, --clickable, --disabled, .mtx-card-action-area (--disabled), .mtx-card__header (-avatar, -content, -action), .mtx-card__title, .mtx-card__subheader, .mtx-card__media, .mtx-card__content, .mtx-card__actions (--start, --center, --between, --disable-spacing) and .mtx-card__actions-end.

Accessibility#

  • Use component="article" or "section" when the card is self-contained content.
  • On a clickable card that is not a <button>/<a>, role="button" and tabIndex={0} are added; its accessible name comes from its content. Avoid an aria-label that does not contain the visible text (WCAG 2.5.3 Label in Name).
  • Prefer CardActionArea (native <button> or <a>): it keeps its semantics and leaves the CardActions buttons as independent controls. Don’t nest buttons inside the area.
  • Images generated with image are decorative unless you pass imageAlt; with CardMedia, use alt.
  • IconButtons in the actions need an aria-label.

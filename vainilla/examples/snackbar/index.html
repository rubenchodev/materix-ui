Snackbar

Brief, temporary notification at an edge of the screen that confirms an action and can offer to undo it.

Basic usage With action Position Duration Consecutive With Alert Quick notice Grid Programmatic usage Manual BEM usage

Basic usage

Declare the snackbar with data-message and open it from JavaScript with open(). It closes with Escape, on a click outside or, if it has data-duration, when the time runs out.

<div data-mtx="snackbar" id="snack-basic" data-message="Message archived" data-duration="4000"></div>

Materix.getInstance(document.getElementById('snack-basic')).open();

With action

data-action generates an action button on the right. Add data-close-on-action so the snackbar closes when it is pressed.

Position

data-anchor accepts six positions combining top/bottom with left/center/right. Below 600px the snackbar spans the full width with an 8px side margin.

Duration

Without data-duration (or with data-duration="none") the snackbar does not close by itself. The timer pauses while the pointer or focus is on it and restarts when they leave.

Consecutive

The component has no queue of its own: two snackbars in the same position overlap. To show them one at a time, close the current one and open the next with open({ message }) when mtx:snackbar:close fires, as in MUI's Consecutive Snackbars example.

With Alert

For notifications with a severity, place an Alert inside a snackbar without its own message and override its background and padding with a page class.

<div data-mtx="snackbar" class="demo-snackbar-alert" data-duration="4000" data-anchor="bottom-left">
  <div data-mtx="alert" data-severity="success" data-variant="filled">Profile updated.</div>
</div>

.demo-snackbar-alert { padding: 0; background-color: transparent; }
.demo-snackbar-alert > .mtx-alert { flex: 1; }

Quick notice with Materix.snackbar.show()

For one-off confirmations you do not need to declare a snackbar: Materix.snackbar.show({ message, action, onAction, duration, anchor }) creates a shared snackbar in <body> the first time (with role="status" and a 4 s duration) and reuses it afterwards. onAction runs when the action is pressed and closes the notice.

Materix.snackbar.show('Link copied');

Materix.snackbar.show({
  message: 'Conversation archived',
  action: 'Undo',
  onAction: () => restoreConversation(),
  duration: 6000,
  anchor: 'bottom-left',
});

Grid

A typical case: action cards in an mtx-grid where each action confirms its result with a shared snackbar.

Programmatic usage

open(options?) shows the snackbar (if it is already open it updates the content and restarts the timer); it accepts { message, action, onAction, duration }. setMessage(text) and setAction(label) change the content without opening it, and close(reason) hides it. Escape only closes the most recent snackbar, and never while a dialog is open on top. The log shows mtx:snackbar:open, mtx:snackbar:action and mtx:snackbar:close for every snackbar on the page.

isOpen: false


      
const snackbar = Materix.getInstance(document.getElementById('snack-api'));
snackbar.open();
snackbar.open({ message: 'Draft saved', action: 'View', onAction: () => openDraft(), duration: 5000 });
snackbar.setMessage('New text');
snackbar.close('done');

document.addEventListener('mtx:snackbar:close', (event) => {
  console.log(event.detail.reason); // timeout | clickaway | escapeKeyDown | action | programmatic
});

    


    

      
Manual BEM usage

      
If the HTML already includes .mtx-snackbar__message and .mtx-snackbar__action, the component reuses them and only adds behavior.

      

        
      

      
<div class="mtx-snackbar mtx-snackbar--bottom-center" id="snack-bem" data-mtx="snackbar"
     data-duration="5000" data-close-on-action>
  <div class="mtx-snackbar__message" role="status">Server-rendered structure</div>
  <button class="mtx-snackbar__action" type="button">Close</button>
</div>

Dialog

A modal window that interrupts the task to ask for a decision or show critical information, with trapped focus and Escape to close.

Basic usage

Declare the container with data-mtx="dialog" and data-title: the backdrop, the panel, the title (with an automatic id and aria-labelledby, so the dialog has an accessible name) and the content are generated. Any button with data-mtx-dialog-open="id" opens it; clicking the backdrop or pressing Escape closes it.

Let apps determine your location to show you nearby results. Press Escape or click outside to close.

<button class="mtx-button mtx-button--contained" data-mtx="button" data-mtx-dialog-open="dlg-basic">Open dialog</button>

<div data-mtx="dialog" id="dlg-basic" data-title="Use the device location">
  <p>Let apps determine your location...</p>
</div>

With actions

Wrap the buttons in .mtx-dialog__actions: the component always places them at the end of the panel, outside the content, even if you do not use .mtx-dialog__content. data-description generates the descriptive text (.mtx-dialog__content-text, equivalent to DialogContentText) and links it with aria-describedby. Elements with data-mtx-dialog-close close the dialog. The main action uses contained and the secondary one text.

Your documents will be copied to the cloud and available on all your devices.
<div data-mtx="dialog" id="dlg-actions" data-title="Turn on sync?">
  <div class="mtx-dialog__content">Your documents will be copied to the cloud...</div>
  <div class="mtx-dialog__actions">
    <button class="mtx-button mtx-button--text" data-mtx="button" data-mtx-dialog-close>Cancel</button>
    <button class="mtx-button mtx-button--contained" data-mtx="button" data-mtx-dialog-close>Turn on</button>
  </div>
</div>

<!-- Without .mtx-dialog__content: text from data-description and actions at the end -->
<div data-mtx="dialog" id="dlg-description" data-title="Discard draft?"
     data-description="The message will be deleted and you will not be able to recover it.">
  <div class="mtx-dialog__actions">...</div>
</div>

Actions alignment

As in MUI, actions go on the right by default (end). Change the alignment with data-align="start|center|end|between" on .mtx-dialog__actions (or data-mtx="dialog-actions"), or set it for the whole dialog with data-actions-align. between separates an auxiliary action on the left from the main ones on the right. data-disable-spacing removes the spacing between buttons.

<!-- Default: on the right -->
<div data-mtx="dialog" id="d1" data-title="Actions on the right">
  <div data-mtx="dialog-actions">…</div>
</div>

<!-- For the whole dialog -->
<div data-mtx="dialog" id="d2" data-title="…" data-actions-align="start">…</div>

<!-- On a specific container: start | center | end | between -->
<div class="mtx-dialog__actions" data-align="between">
  <button class="mtx-button mtx-button--text" data-mtx="button">Help</button>
  <div class="mtx-d-flex mtx-gap-1">…</div>
</div>

Sizes

The max width is controlled with classes on the container: mtx-dialog--max-sm (24rem), --max-md (32rem, default), --max-lg (48rem), --max-xl (64rem) and mtx-dialog--full (full screen). The panel always takes 100% of the available width up to that maximum.

Max width
Full screen
Max width of 24rem, ideal for short confirmations.
Max width of 32rem; this is the default value.
Max width of 48rem, useful for two-column forms.
Max width of 64rem, for tables or previews.

The panel takes the whole window and loses its rounded corners, like the MUI fullScreen dialog. It is the recommended pattern on mobile for long tasks.

Destructive confirmation

For irreversible actions use a title phrased as a question, explain the consequence and color the action with mtx-button--error. With data-dialog-autofocus the initial focus goes to "Cancel", the safe option.

Form inside a dialog

A <form> can hold the content and the actions. The first field gets focus on open (or the one marked with data-dialog-autofocus, which works directly on <input data-mtx="text-field">: in "Subscribe" focus goes to the email because the name is already filled in) and Tab does not leave the panel. On submit it closes with close(). Use .mtx-dialog__content-text for the explanatory text; if the content starts directly with a field, the component reserves space at the top so the floating label is not clipped.

Scroll: paper and body

With data-scroll="paper" (default) the content scrolls inside the panel; add mtx-dialog__content--dividers to separate areas and mtx-dialog__actions--sticky to pin the actions. With data-scroll="body" the panel grows with its content and the dialog container is what scrolls (like MUI scroll="body").

Modal behavior

By default the dialog closes on a backdrop click and with Escape. data-disable-backdrop-close and data-disable-escape force the user to choose an explicit action. While it is open, page scrolling is locked.

Clicking outside the panel does not close it; Escape does.
Neither the backdrop nor Escape closes this dialog: only the buttons do.

Stacked layers and Escape

A popover, a menu and a tooltip opened inside a dialog join the shared layer stack: each Escape closes only the top layer (a visible tooltip first), and interacting with them never closes the dialog.

Grid

Inside the content you can use mtx-grid for multi-column forms; combine it with mtx-dialog--max-lg to give the columns room.

Programmatic usage

Get the instance with Materix.getInstance(el) and call open() or close(reason). The log shows the mtx:dialog:open and mtx:dialog:close events with their detail.reason; try closing with Escape, the backdrop or the button.


      

        
Opened with Materix.getInstance(el).open().

        

          
        

      

      
const dialog = Materix.getInstance(document.getElementById('dlg-api'));
dialog.open();
dialog.close('saved');   // detail.reason === 'saved'

document.addEventListener('mtx:dialog:close', (event) => {
  console.log(event.target.id, event.detail.reason);
});

    


    

      
Manual BEM usage

      
The full structure lets you link the title with aria-labelledby and the description with aria-describedby, and pin the title and actions with the --sticky modifiers.

      

        
      

      

        

        

          
BEM structure

          
Rendered on the server: the component does not duplicate nodes and only adds behavior.

          

            
            
          

        

      

      
<div class="mtx-dialog mtx-dialog--max-sm" id="dlg-bem" data-mtx="dialog"
     aria-labelledby="dlg-bem-title" aria-describedby="dlg-bem-desc">
  <div class="mtx-dialog__backdrop" data-mtx-dialog-close></div>
  <div class="mtx-dialog__paper" role="dialog" aria-modal="true">
    <h2 class="mtx-dialog__title mtx-dialog__title--sticky" id="dlg-bem-title">BEM structure</h2>
    <div class="mtx-dialog__content" id="dlg-bem-desc">...</div>
    <div class="mtx-dialog__actions mtx-dialog__actions--sticky">
      <button class="mtx-button mtx-button--text" data-mtx="button" data-mtx-dialog-close>Cancel</button>
      <button class="mtx-button mtx-button--contained" data-mtx="button" data-mtx-dialog-close>OK</button>
    </div>
  </div>
</div>

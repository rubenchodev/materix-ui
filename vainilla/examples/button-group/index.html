Button Group

Groups related buttons into a single piece with joined borders, separators and inherited variant, size and color.

Basic usage Variants Sizes With icons Colors Orientation Full width States Split button Grid layout Programmatic usage Manual BEM usage

Basic usage

A container with data-mtx="button-group" and plain buttons inside: the group turns them into Buttons, applies its variant (outlined by default) and adds role="group". Give it a name with data-label or aria-label.

<div data-mtx="button-group" data-variant="contained" data-label="Basic actions">
  <button>One</button>
  <button>Two</button>
  <button>Three</button>
</div>

Variants

data-variant="outlined|contained|text", as in MUI. Outlined overlaps the borders; contained separates with the dark shade of the color and moves the elevation to the group; text separates with a 50% line.

Sizes

data-size="small|medium|large" is inherited by every button (32, 40 and 48px), aligned with a TextField and IconButton of the same height.

With icons

Each child accepts the Button attributes (data-start-icon, data-end-icon). For icon-only buttons, use a direct .material-icons and an aria-label: the group compacts their padding.

Colors

data-color accepts the palette colors and inherit; a child with its own data-color keeps it.

Orientation

data-orientation="vertical" stacks the buttons (keeps role="group", which does not allow aria-orientation).

Full width

data-full-width takes the full width and splits the space evenly.

States

Hover or use Tab to see hover and focus (the active button is drawn above the neighboring borders). data-disabled disables the whole group; a single child can be disabled on its own. data-disable-elevation removes the shadow of the contained group.

Split button

MUI pattern: the primary action plus an arrow that opens a Menu with data-open-menu. The menu handles aria-haspopup, aria-expanded and the keyboard; choosing an option (mtx:menu:select) updates the text of the primary button. data-position-anchor anchors the menu to the whole group (as MUI does) while focus still returns to the arrow.

Create a merge commit
Squash and merge
Rebase and merge
<div data-mtx="button-group" data-variant="contained" data-label="Merge pull request" id="split-group">
  <button id="split-main">Squash and merge</button>
  <button aria-label="Choose merge strategy" data-open-menu="#split-menu">
    <span class="material-icons" aria-hidden="true">arrow_drop_down</span>
  </button>
</div>
<div data-mtx="menu" id="split-menu" data-position-anchor="#split-group">
  <div data-mtx="menu-item" role="menuitemradio" data-value="Create a merge commit">Create a merge commit</div>
  <div data-mtx="menu-item" role="menuitemradio" data-value="Squash and merge" data-checked>Squash and merge</div>
</div>

document.getElementById('split-menu').addEventListener('mtx:menu:select', (e) => {
  document.getElementById('split-main').textContent = e.detail.item.dataset.value;
});

Grid layout

With data-full-width the group adapts to the mtx-grid column.

Programmatic usage

The instance exposes disable(), enable(), disabled, buttons and refresh() (after adding or removing buttons).


      
const group = Materix.getInstance(document.getElementById('group-api'));
group.disabled ? group.enable() : group.disable();

const extra = document.createElement('button');
extra.textContent = 'Three';
group.element.appendChild(extra);
group.refresh();

Internationalization

Choose the language of Materix UI's built-in strings per page, per container or per component, override individual strings and register new languages.

Materix translates the strings it generates itself: the DateTimePicker buttons and month names, the Select search box and counters, and the TablePagination labels. Your own text (labels, helper text, content) is yours to write in whatever language you want.

Two languages ship out of the box: en (English, the default) and es (Spanish).

How the language is resolved#

For each component, Materix uses the first registered language it finds, in this order:

  1. data-locale, data-lang or lang on the element itself or on its closest ancestor that has one of those attributes (<html lang> does not count at this step; data-locale/data-lang on <html> do).
  2. The global language set explicitly with setLocale().
  3. The lang attribute of <html>.
  4. en.

Regional codes are reduced to their base language: es-MX and es-ES resolve to es.

Until you call setLocale(), <html lang> determines the language of the whole page:

<html lang="es">  <!-- calendar, Select and pagination in Spanish -->
info

setLocale() overrides <html lang>, not a local lang

On a page with <html lang="es">, Materix.setLocale('en') switches the components to English. A lang, data-locale or data-lang on the component or on an ancestor below <html> still wins, so a <section lang="es"> stays in Spanish. resetLocale() discards the explicit language and goes back to following <html lang>.

Per-container or per-component language#

data-locale on a container or on the component itself forces its language:

<html lang="en">
  ...
  <!-- This picker in Spanish -->
  <input data-mtx="date-picker" data-locale="es">

  <!-- Everything in this block in Spanish -->
  <section data-locale="es">
    <select data-mtx="select" data-label="Tags" data-search multiple>
      <option>Design</option>
      <option>Development</option>
    </select>
  </section>
</html>

data-lang is equivalent to data-locale. If the closest ancestor declares an unregistered language (for example lang="fr" without having added fr), Materix skips straight to the explicit global language, then to <html lang> and finally to en.

info

In the DateTimePicker, use the two-letter code in data-locale (es, not es-MX). The picker reads that attribute as is, and a regional code on its own element falls back to English.

Switching languages at runtime#

setLocale() changes the global language and dispatches mtx:locale:change on document (the deprecated alias mtx:localechange is still dispatched until 1.0). DateTimePicker, Select and TablePagination listen for it and re-render their strings:

Materix.setLocale('es');   // true
Materix.getLocale();       // 'es'
Materix.setLocale('es-AR'); // true: reduced to 'es'
Materix.setLocale('fr');   // false: not registered, keeps the current one and logs a console warning

setLocale() takes precedence over <html lang>, so it is enough on its own. Keeping <html lang> in sync is still good practice for screen readers and the browser:

/**
 * Changes the language of the page and its components.
 * @param {string} locale Registered language code ('en', 'es'...).
 */
function changeLanguage(locale) {
  document.documentElement.lang = locale;
  Materix.setLocale(locale); // dispatches mtx:locale:change and the components update
}

Listen for the same event to update your own strings:

document.addEventListener('mtx:locale:change', (event) => {
  console.log('New language:', event.detail.locale);
});

Overriding a string on a component#

data-* attributes take precedence over any dictionary. Use them to change a specific string without changing the language:

<input data-mtx="date-picker" data-ok-text="Confirm" data-cancel-text="Go back" data-today-text="Right now">

<select data-mtx="select" data-label="Cities" multiple data-search data-actions-box
        data-none-results-text="Nothing matches “{0}”"
        data-select-all-text="Check all"
        data-deselect-all-text="Uncheck all">
  <option>Bogotá</option>
  <option>Madrid</option>
</select>

Adding a language#

addLocale(code, dictionary) registers a new language (or replaces an entire one). Missing keys fall back to English, so you can start with just the ones you need:

Materix.addLocale('fr', {
  name: 'Français',
  dateTimePicker: {
    today: "Aujourd'hui",
    cancel: 'Annuler',
    ok: 'OK',
    months: ['Janvier', 'Février', 'Mars', 'Avril', 'Mai', 'Juin',
             'Juillet', 'Août', 'Septembre', 'Octobre', 'Novembre', 'Décembre'],
    weekdays: ['D', 'L', 'M', 'M', 'J', 'V', 'S'],
  },
  select: {
    searchPlaceholder: 'Rechercher…',
    noneResultsText: 'Aucun résultat pour « {0} »',
  },
  tablePagination: {
    rowsPerPage: 'Lignes par page :',
    of: 'sur',
  },
});

document.documentElement.lang = 'fr';
Materix.setLocale('fr');

Register the language before the components that use it are initialized, or call setLocale() afterwards so they update.

Modifying an existing language#

updateLocale(code, partial) deep-merges the keys you pass and keeps the rest. If the language doesn’t exist, it creates it:

Materix.updateLocale('en', {
  dateTimePicker: { ok: 'Done' },
  select: { searchPlaceholder: 'Filter…' },
});

Components that have already rendered don’t update on their own after updateLocale: call Materix.setLocale(Materix.getLocale()) to dispatch mtx:locale:change.

API reference#

FunctionReturnsDescription
setLocale(code)booleanSets the global language (it takes precedence over <html lang>) and dispatches mtx:locale:change. false if it is not registered.
resetLocale()voidDiscards the language set with setLocale() (back to <html lang>, then en) and dispatches mtx:locale:change. Available as Materix.i18n.resetLocale().
getLocale()stringEffective global language: the one set with setLocale(), otherwise <html lang> (if registered), otherwise en. t() and getDictionary() without a language use this value.
addLocale(code, dictionary)voidRegisters or replaces an entire language.
updateLocale(code, partial)voidMerges keys into an existing language (or creates it).
t(component, key, params?, fallback?, locale?)*Returns a translation. params interpolates {0} (array) or {name} (object).

Materix.getComponentLocale(document.querySelector('#date')); // 'es'

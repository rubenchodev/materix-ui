Menu

Temporary list of options anchored to a trigger: icons, dividers, selection, submenus, context menu and full keyboard navigation.

play_circleLive example codeSource code open_in_newMUI reference
Declarative initialization data-mtx="menu"

Menu displays a temporary list of actions or options on an elevated surface, anchored to the element that opens it, like MUI’s Menu (Popper + Paper + List). Use it for contextual actions on an item (edit, duplicate, delete), account menus or compact toolbars. To pick a value in a form use Select; for the app’s main navigation, use a Drawer or Tabs.

Basic usage#

A trigger with data-open-menu="#id" and a data-mtx="menu" container with that id, holding data-mtx="menu-item" items. Clicking opens it below the trigger; clicking an option, clicking outside the menu, Escape or Tab closes it.

Profile
My account
Log out
Basic menu 
<button class="mtx-button mtx-button--outlined" data-mtx="button" data-open-menu="#doc-menu-basic">Open menu</button>
<div data-mtx="menu" id="doc-menu-basic">
  <div data-mtx="menu-item">Profile</div>
  <div data-mtx="menu-item">My account</div>
  <div data-mtx="menu-item">Log out</div>
</div>

When it opens, the menu container is moved to a portal at the end of <body> so it is not clipped by the overflow or z-index of its ancestors. It remains reachable with document.getElementById.

Triggers#

A menu needs an id and an explicit trigger; there is no implicit trigger. Three options, from most to least recommended:

  1. data-open-menu="#id" (or its alias data-mtx-menu-trigger="#id") on the button. It also works for triggers added after the menu is initialized (for example, the actions button of each row in a table rendered by JavaScript): clicks are handled through delegation.
  2. aria-controls="id" on an element that exists when the menu initializes.
  3. data-anchor="selector" on the menu itself: that element becomes both anchor and trigger.

The component adds aria-haspopup="menu", a synchronized aria-expanded and aria-controls (when missing) to the trigger. Without any of these mechanisms the menu only opens programmatically with open(anchor).

data-selected marks the current option with the action-selected background, and it receives focus when the menu is opened from the keyboard. data-disabled dims the option and excludes it from keyboard and click interaction (aria-disabled="true"). Hover over the items to see the hover background.

Checkable options#

With role="menuitemcheckbox" the item toggles aria-checked when clicked; with role="menuitemradio" it becomes checked and unchecks the others in its group (role="group" or the menu). data-checked sets the initial state and the component adds the mtx-menu-item__check mark, visible only while checked. mtx:menu:select includes detail.checked.

Positioning#

The menu is placed below the trigger, aligned to its left edge with a 4px gap. If it does not fit below and there is more room above, it opens upwards; its maximum height is the available space (with internal scrolling). While open it follows the trigger as the page scrolls, the window resizes or the trigger or menu change size, and it closes if the trigger leaves the viewport. Submenus open to the right of their item (to the left in RTL, dir="rtl"), flip to the other side when there is no room and shift vertically to stay inside the viewport.

  • data-anchor="selector" uses another element as the anchor (and also turns it into a trigger). data-position-anchor="selector" only positions the menu against another element without turning it into a trigger (for example the whole ButtonGroup of a split button); focus still returns to the trigger. The menu’s previous sibling is no longer used as an implicit anchor: always declare the trigger (see “Triggers”).
  • data-match-width makes the menu’s minimum width match the anchor’s.
  • data-transform-origin forces the origin of the opening animation (top, bottom…).

Submenus#

An item with data-submenu-trigger and data-open-menu="#id" opens another menu marked with data-submenu to its right (or to its left if it does not fit). It opens on hover, on click or with →, and closes with ←. The chevron_right indicator is added automatically.

Context menu#

Materix.Menu.createContextMenu(selector, items) builds a menu from JSON that opens on right-click at the pointer position. Each item accepts label, icon, image, disabled, divider, submenu and action(item, event).

API reference#

Data attributes#

Trigger

AttributeValuesDefaultDescription
data-open-menuMenu #id—The element opens and closes (toggles) that menu on click and acts as its anchor. It gets aria-haspopup="menu", aria-expanded and aria-controls. Also works when added after initialization (delegation).
data-mtx-menu-triggerMenu #id or id—Alias of data-open-menu.
aria-controlsMenu id—An element present at initialization whose aria-controls equals the menu id is also a trigger.

Menu (data-mtx="menu")

AttributeValuesDefaultDescription
data-anchorCSS selector—Positioning anchor and additional trigger (takes precedence over data-open-menu as the anchor). Without a declared trigger, the menu only opens with open(anchor).
data-position-anchorCSS selector—Positioning-only anchor (does not open the menu), e.g. the group of a split button.
data-match-widthboolean—Minimum width equal to the anchor’s.
data-transform-originCSS value (top, bottom…)based on placementOrigin of the opening animation.
data-openboolean—Opens the menu on initialization.
data-submenuboolean—Turns it into a submenu: it opens to the right of the trigger item and also on hover.

MenuItem (data-mtx="menu-item")

AttributeValuesDefaultDescription
data-iconMaterial Icons name—Inserts a decorative icon before the text.
data-selectedboolean—Selected state (mtx-menu-item--selected).
data-disabledboolean—Disables the item (mtx-menu-item--disabled, aria-disabled).
data-denseboolean—32px minimum height.
data-disable-guttersboolean—No horizontal padding.
data-submenu-triggerboolean—The item opens a submenu (with data-open-menu) and does not close the menu when clicked.
data-dividerboolean—Turns the item into a separator (role="separator", mtx-menu-item--divider class, not focusable).
rolemenuitem, menuitemcheckbox, menuitemradiomenuitemWith menuitemcheckbox a click toggles aria-checked; with menuitemradio it checks the item and unchecks the rest of its group.
data-checkedboolean—With role="menuitemcheckbox" or menuitemradio, the initial aria-checked state.
data-valueText—Free-form value to identify the option in mtx:menu:select.

Accessibility#

  • The menu gets role="menu" and each item role="menuitem" (or the menuitemcheckbox / menuitemradio you declare, with a synchronized aria-checked) and tabindex="-1"; separators get role="separator". The trigger gets aria-haspopup="menu", aria-controls and a synchronized aria-expanded.
  • When opened from the keyboard, focus moves to the selected option or the first enabled one; when opened with the mouse, to the menu container. When it closes with Escape or after a choice, focus returns to the trigger.
  • Generated icons are decorative (aria-hidden). If the trigger is an icon-only button, give it an aria-label.
  • Disabled items carry aria-disabled="true" and are skipped by the keyboard.
